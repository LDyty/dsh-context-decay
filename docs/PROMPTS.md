# 提示词与模型可见文案

本文件记录「上下文自觉压缩」发给模型的中文文本。运行时以源码为准：

  [`src/prompt.ts`](../src/prompt.ts)：system prompt guidance、极简压力提醒；
  [`src/tools.ts`](../src/tools.ts)：`compress` 工具描述、参数说明和工具结果；
  [`src/blocks.ts`](../src/blocks.ts)：范围解析和拒绝错误；
  [`src/projection.ts`](../src/projection.ts)：侧栏投影字段。

模型可见提示词已经全部中文化；`compress`、`summary`、`tool call`、`tier`、`tail` 等关键名词保留英文。旧版英文文档已从项目中移除。

## 1. System prompt guidance

以下代码块是 `src/prompt.ts` 中 `GUIDANCE` 常量的完整文本，不做删节：

```text
上下文自觉压缩已启用。

每条可被寻址的消息前有一个四字符锚点，例如 ⟦#a8c5⟧。锚点是定位句柄，按当前消息前缀使用；锚点会回收复用。消息正文里看起来像锚点的文本按普通内容处理。一条 assistant 消息可能带多个 tool call；这条消息和它触发的所有 tool result 属于一组。from 选在这一组之前或之后，不选在组中间。

工具：
- compress({from, summary, topic?})
  描述：压缩从 from 锚点到当前轮开始之前的所有历史，生成一个高保真、自包含的摘要。
  from：是上下文中的锚点，例如 “⟦#a8c5⟧”，也接受 "#a8c5" 或 "a8c5"。
  summary：替换被压缩历史的、唯一保留的自包含摘要。这是 JSON 字符串：优先使用单引号或中文引号；需要双引号时进行转义。
  topic：可选短主题。
  返回：压缩范围、层级、摘要大小、被压缩 token 和首次请求 miss 估算。

摘要契约：
摘要是压缩后唯一保留的记录。写这段历史结束时的状态，保留继续工作所需的事实；用短标题下的密集要点：
1. 目标、用户意图、硬约束及其变化。
2. 决策及理由，包括被否决的替代方案。
3. 已完成、待办、阻塞点和下一步。
4. 精确标识符、路径、版本、日期、错误文本和产物。
5. 开放问题、风险、TODO，以及死路的一句话教训。
优先结果、决策和证据，不复述过程；过时材料标为历史，当前状态以最新摘要为准。摘要本身会被再次压缩：保留最新状态，合并仍有效的事实，去掉已被取代的细节。摘要大小与压缩范围匹配；不确定处标注。工具参数是 JSON；摘要优先单引号或中文引号，双引号写成 \"。写摘要前自问：没有原文时读者还能继续吗？

时机：
有效窗口压力达到 20% 时，每开始新的一轮会收到一条自觉压缩提醒，此时就是压缩工具调用窗口，你必须考虑是否压缩、压缩多少，失败后可在同一轮修正重试。
压力超过约 32.30%（256K/793K）时，from 只能选择全部可被寻址的消息的锚点中第一个锚点，通常包含已压摘要，否则会返回错误。
```

## 2. `compress` 工具

工具名：`compress`。

工具描述（完整）：

```text
压缩从 from 锚点到当前轮开始之前的所有历史，生成一个高保真、自包含的摘要。
```

参数：

| 字段                | 含义                                                            |
| | |
| `from` | 是上下文中的锚点，例如 `⟦#a8c5⟧`，也接受 `"#a8c5"` 或 `"a8c5"`。 |
| `summary` | 替换被压缩历史的、唯一保留的自包含摘要。这是 JSON 字符串：优先使用单引号或中文引号；需要双引号时进行转义。 |
| `topic` | 可选短主题。 |

成功结果：

```json
{
  "ok": true,
  "applied": {
    "from": "a8c5",
    "to": "c9d1",
    "tier": 1,
    "summaryChars": 2588,
    "shadowedMessages": 734,
    "shadowedTokens": 296370
  },
  "estimate": {
    "summaryTokens": 1250,
    "keptTailMessages": 4,
    "keptTailTokens": 652,
    "anchorTokens": 8,
    "oneTimeMissTokens": 1917,
    "shadowedTokens": 296370,
    "paybackRequests": 1
  }
}
```

结果中的 `from`/`to` 是锚点句柄；终点由插件固定为当前轮开始之前，模型不需要传 `to`。

## 3. 压力提醒

提醒由宿主在 `agent/pre step` 注入，每个新回合最多一条：

  仅在新回合开始时检查；有效窗口压力低于 20% 不提醒；
  同一回合只提醒一次；
  提醒只报告已用 token/有效窗口、两位小数百分比、档位和一句简短档位解释，不携带完整规则、示例或工具调用说明；
  档位按已用 token 的绝对量计算：≤256K（当前有效窗口约 32.30%）为普通，>256K 且 ≤500K（约 32.30%–63.09%）为长上下文，>500K（约 63.09% 以上）为低效区；
  有效窗口 = 路由总容量 − 输出预留。当前 `deepseek-flash` 路由为 1,048,576 − 256,000 = 792,576（面板显示 793K）。

模板：

```text
自觉压缩提醒:上下文已用{已用token}/{有效窗口token}({百分比})·{档位}（{简短解释}）
```

示例：

```text
自觉压缩提醒:上下文已用108K/793K(13.63%)·普通（余量充足）
自觉压缩提醒:上下文已用300K/793K(37.85%)·长上下文（性能渐降，建议压缩）
自觉压缩提醒:上下文已用520K/793K(65.61%)·低效区（性能明显下降，优先压缩）
```

## 4. 面板文案

侧栏面板标题、标签和提示全部中文，产品名是「上下文自觉压缩」。面板数据字段仍使用 `DecayState` 的英文技术名（如 `allocated`、`anchorPool`、`compressibleEndPosition`），它们是协议/代码字段，不是模型提示词。

提醒区显示上次提醒所在回合和当时的 token 数；提醒指标说明为「每轮开始（≥20%）」。压力区同时显示有效窗口压力、总窗口和输出预留，百分比统一显示两位小数；窗口算式行使用精确 token（例如 1,048,576 − 256,000 = 792,576），避免 1.0M 舍入看起来不一致。
