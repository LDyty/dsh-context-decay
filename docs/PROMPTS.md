# 提示词与模型可见文案

本文件记录「上下文自觉压缩」发给模型的中文文本。运行时以源码为准：

  [`src/prompt.ts`](../src/prompt.ts)：system prompt guidance、极简压力提醒；
  [`src/tools.ts`](../src/tools.ts)：`compress` 工具描述、参数说明和工具结果；
  [`src/blocks.ts`](../src/blocks.ts)：范围解析和拒绝错误；
  [`src/projection.ts`](../src/projection.ts)：侧栏投影字段。

模型可见提示词已经全部中文化；`compress`、`span`、`summary`、`tool call`、`tier`、`tail` 等关键名词保留英文。旧版英文文档已从项目中移除。

## 1. System prompt guidance

以下代码块是 `src/prompt.ts` 中 `GUIDANCE` 常量的完整文本，不做删节：

```text
上下文自觉压缩已启用。

本会话中，每条可被模型寻址的消息前都会显示一个四字符锚点，例如 ⟦#a8c5⟧。锚点是定位句柄，配合当前消息上打印的句柄使用；写摘要、文件或回复时，让内容保持自包含。消息正文里看起来像 ⟦#a8c5⟧ 的文本按普通内容处理。锚点会回收复用，句柄本身不表示消息先后；请以当前消息上打印的锚点为准。少数 assistant 回合只请求工具、没有可见文本，因此没有锚点；把 span 边界放在有锚点的消息上。

压缩区域显示为 ⟦#<from>⟧ 摘要 ⟦#<to>⟧。这一对就是该区域的句柄：右侧锚点是第一条保留消息，或者是可压缩历史末尾的 "end"。摘要会替代原内容，请把继续工作需要的事实完整写进摘要。

同一条 assistant tool-call 消息的所有结果作为一个整体压缩；span 边界放在整个 tool-call 组之前或最后一个结果之后。

工具：
- compress：一次调用可以传多个 span，例如 compress({spans:[{from:"⟦#a8c5⟧", to:"⟦#c9d1⟧", summary:"..."}, {from:"⟦#e2f3⟧", to:"end", summary:"..."}]})。每个 span 的 "from" 是第一条被压缩消息（含），"to" 是第一条保留消息（不含）或 "end"；这些 span 分别覆盖不同区域，相邻 span 可以相接。锚点从消息前缀复制，例如 "⟦#a8c5⟧"（也接受裸 "#a8c5" 或 "a8c5"）。单段也可用同样结构。示例锚点只作说明；使用当前会话可见的锚点。锚点参数是工具值，摘要保持自包含。结果会报告配对、层级、摘要大小、被遮蔽 token、保留 tail 和一次性 miss 估算。

摘要契约：
摘要是被压缩 span 唯一剩下的记录。把 span 结束时的状态写成历史；摘要里的待办事项在继续执行前重新核实。
空间紧张时，大致按这个顺序保留：
1. 目标、用户意图、硬约束，以及它们的任何变化。
2. 决策及其理由，包括被否决的替代方案。
3. 当前进度：已完成、待办、阻塞点和下一步。
4. 继续工作需要的精确事实：名称、标识符、位置或链接、版本、日期、数字、错误文本，以及输出或产物的描述。
5. 开放问题、风险、TODO，以及死路的一句话教训。
摘要聚焦结果、决策、证据和仍然开放的事项；原始日志、重复材料、逐步过程和已经解决的闲聊留在历史层。某个细节以后可能还要核对时，保留它，或者把来源留在可见区域。
用短标题下的密集要点写高保真摘要，保留正确、有用的事实、精确标识符、路径、版本、决策和证据。摘要大小与 span 匹配：大的多阶段范围通常明显多于几百 token；字符上限是上限，目标由内容决定。事实保持准确；不确定的地方标注，或者省略。
工具参数是 JSON。摘要中优先使用单引号或中文引号；需要引用带双引号的代码时，把每个双引号写成 \"。在保留关键事实的前提下，让摘要尽量紧凑。范围很大时，拆成多个 span，让每个摘要对应清楚的范围。
调用 compress 前检查：没有原文时读者还能继续吗？当前状态、开放事项和精确事实都保住了吗？

压缩已有摘要（更高 tier）时，做提炼而不是复述：保留结果、决策与理由、约束、仍然开放的目标和风险；过程细节留在历史层。已被取代或过时的材料标记为历史，当前状态以最新摘要为准。

压缩规则：
时机：每开始新的一轮，如果有效窗口压力达到 20%，你会收到一条极简提醒，显示已用 token/有效窗口、百分比和档位（普通 / 长上下文 / 低效区；超过有效窗口约 32% 为长上下文，性能逐渐下降，应尽快考虑在回合开始时压缩；超过有效窗口约 63% 为低效区，性能明显下降，应优先考虑在回合开始时压缩）。提醒只是信号，是否压缩、压缩多少由你决定。压缩只在每个新回合开始时进行。如果回合开始时的压缩失败，可以在同一回合修正后重试；其他工具执行后不再接受压缩。
通常，阶段或决策点结束、长输出已提炼成结论、话题切换、完成交接时，以及一个独立子问题已闭环、大段工具输出已提炼成结论、错误已定位到关键行时，适合在回合开始时压缩。

深扫规则：有效窗口压力超过约 33% 时，这次压缩必须做深扫：开头对齐当前可见历史中最老的已消费锚点，结尾对齐最新安全可压边界。第一个 span 从最老的可见锚点开始；摘要块也算已消费历史，第一个 span 从它开始。最后一个 span 结束在最新安全可压边界（通常写 "end"，或当前回合第一条可见锚点）。中间仍活跃的内容可以跳过，其余已消费内容都进入摘要。
整次深扫可以只用一个 span 加一个摘要，也可以拆成几个相邻 span，各自写摘要。摘要详略由你根据信息重要性取舍。span 之间只跳过仍然活跃的内容；每段只覆盖一次，相邻段可以相接。每个 assistant tool-call 组完整地留在同一个 span 中。
“安全”指内容已经消费完、可以完整写进摘要；仍然活跃的内容留在可见区域。

调用前自检：
1. 先找当前可见历史最老的锚点；摘要块也算已消费历史，第一个 from 从它开始。
2. 再找当前回合第一条可见锚点；最后一个 to 用它，或确认 end 只到可压缩历史末尾、不会纳入当前回合。
3. to 是排他边界：to 命名的消息会保留；要包含某条消息，to 必须是它后面的第一条可见锚点。
4. 确认第一个 span 覆盖最老历史、最后一个 span 到达安全边界。
正例：from "⟦#a8c5⟧"（最老可见锚点，即使它是摘要块）→ to "⟦#c9d1⟧"（当前回合第一条可见锚点）；"⟦#c9d1⟧" 保留。
错例：from "⟦#e2f3⟧"（跳过最老摘要块）→ 漏压最老一段。

规则：当前回合是受保护区域；压缩 span 在它之前结束。如果 "to" 是当前回合第一条可见锚点，它前面的无锚点消息留在可见区域，压缩覆盖当前回合之前的历史；"end" 表示可压缩历史的末尾。优先压缩老的、已经完全消费的工作，保留当前工作。压缩会让从 "from" 开始的缓存前缀失效：压缩范围之后的消息会重新无缓存发送一次，所以很早开始压缩又留下很大 tail 的成本更高。优先压缩一段连续的已消费工作，并尽量把 "to" 放晚。中间需要保持可见的内容，在它两侧各压缩一个已消费 span，让它留在可见区域；缓存成本仍从最早压缩位置算起。一次调用尽量传入所有已消费 span：分多次调用会再次让前缀失效。在保留下一步需要的事实的前提下，让 tail 保持精简。
```

## 2. `compress` 工具

工具名：`compress`。

工具描述（完整）：

```text
把已经消费完的历史压缩成自包含的有损摘要。一次调用可以传多个 span，例如 compress({spans:[{from:"⟦#a8c5⟧", to:"⟦#c9d1⟧", summary:"..."}, {from:"⟦#e2f3⟧", to:"end", summary:"..."}]})。每个 span 都是可见锚点的半开区间：“from” 是第一条被压缩消息（含），“to” 是第一条保留消息（不含），或者可压缩历史末尾的 “end”。这些 span 分别覆盖不同区域，相邻 span 可以相接。锚点从消息前缀原样复制，例如 “⟦#a8c5⟧”；也接受裸句柄 “#a8c5” 或 “a8c5”。示例锚点只是说明；使用当前会话可见的锚点。当前回合是受保护区域，压缩 span 在它之前结束；如果 “to” 是它的第一条可见锚点，之前的无锚点消息留在可见区域。同一个 assistant tool-call 组完整地留在同一个 span 中；把边界放在组之前或最后一个结果之后。压缩只在每个新回合开始时进行；如果回合开始时的压缩失败，可以在同一回合修正后重试，其他工具执行后不再接受压缩；有效窗口压力超过约 33% 时，这次压缩必须做深扫：第一个 span 从最老的可见锚点开始，摘要块也算已消费历史；最后一个 span 结束在最新安全可压边界（通常用 “end”，它只到可压缩历史末尾、不会纳入当前回合；或当前回合第一条可见锚点）。to 是排他边界，它命名的消息会保留。中间仍活跃的内容可以跳过，其余已消费内容进入摘要。摘要会替代被压缩内容，请遵循 guidance 中的摘要契约，写全仍然重要的事实。结果会报告配对、层级、摘要字符数、被遮蔽 token、保留 tail 和一次性 miss 估算。
```

参数：

| 字段                | 含义                                                            |
|                     |                                                                 |
| `spans`           | 要压缩的已消费区域；每个区域在一次调用中出现一次，相邻 span 可以相接。 |
| `spans[].from`    | 闭区间锚点，例如`⟦#a8c5⟧`（也接受裸 `#a8c5` 或 `a8c5`）。 |
| `spans[].to`      | 排他锚点，例如`⟦#c9d1⟧`，或 “end”。                       |
| `spans[].summary` | 替代该 span 的自包含摘要；保留状态、决策、精确事实和开放事项。这是 JSON 字符串：优先使用单引号或中文引号；需要双引号时进行转义。 |
| `spans[].topic`   | 可选短主题，记录到摘要块账本。                                  |

## 3. 压力提醒

提醒由宿主在 `agent/pre step` 注入，每个新回合最多一条：

  仅在新回合开始时检查；有效窗口压力低于 20% 不提醒；
  同一回合只提醒一次；
  提醒只报告已用 token/有效窗口、百分比和档位，不携带规则、示例或工具调用说明；
  档位按已用 token 的绝对量计算：≤256K（当前有效窗口约 32%）为普通，>256K 且 ≤500K（约 32%–63%）为长上下文，>500K（约 63% 以上）为低效区；
  有效窗口 = 路由总容量 − 输出预留。当前 `deepseek-flash` 路由为 1,048,576 − 256,000 = 792,576（面板显示 793K）。

模板：

```text
自觉压缩:上下文已用{已用token}/{有效窗口token}({百分比})·{档位}
```

示例：

```text
自觉压缩:上下文已用108K/793K(14%)·普通
自觉压缩:上下文已用300K/793K(38%)·长上下文
自觉压缩:上下文已用520K/793K(66%)·低效区
```

## 4. 面板文案

侧栏面板标题、标签和提示全部中文，产品名是「上下文自觉压缩」。面板数据字段仍使用 `DecayState` 的英文技术名（如 `allocated`、`anchorPool`、`compressibleEndPosition`），它们是协议/代码字段，不是模型提示词。

提醒区显示上次提醒所在回合和当时的 token 数；提醒指标说明为「每轮开始（≥20%）」。压力区同时显示有效窗口压力、总窗口和输出预留；窗口算式行使用精确 token（例如 1,048,576 − 256,000 = 792,576），避免 1.0M 舍入看起来不一致。
